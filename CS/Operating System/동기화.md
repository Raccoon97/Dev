# 동기화 (Synchronization) 란?
- 여러 개의 프로세스 또는 스레드가 **공유 자원에 동시에 접근** 할 때 발생하는 문제를 해결하기 위한 기법이다.
- 동시성 환경에서 데이터의 **일관성과 무결성** 을 보장하는 것이 목적이다.

<br><br><br>

# Critical Section
- **임계 영역 (Critical Section)** : 공유 자원에 접근하는 코드 영역.
- 한 번에 **하나의 스레드만** 접근할 수 있어야 한다.

### 임계 영역 해결 조건
1. **Mutual Exclusion (상호 배제)** : 한 번에 하나의 스레드만 진입
2. **Progress (진행)** : 임계 영역에 진입하려는 스레드가 있다면 누군가는 반드시 진입해야 함
3. **Bounded Waiting (한정 대기)** : 대기 시간에 한계가 있어야 함 (Starvation 방지)

<br><br><br>

# Race Condition
- 여러 스레드가 **동시에** 같은 자원에 접근해 **실행 순서에 따라 결과가 달라지는** 현상.

```swift
// Race Condition 예시
var counter = 0

// 여러 스레드에서 동시에 실행
for _ in 0..<1000 {
    DispatchQueue.global().async {
        counter += 1  // 여러 스레드가 동시에 접근 → 결과 예측 불가
    }
}
```

- `counter += 1` 은 세 단계로 이루어진다 : **읽기 → 증가 → 쓰기**
- 두 스레드가 동시에 이 연산을 수행하면 일부 증가 연산이 유실될 수 있다.

<br><br><br>

# Mutex
- **MUTual EXclusion** 의 약자로, **상호 배제** 를 위한 동기화 도구이다.
- **Lock** 과 **Unlock** 으로 임계 영역을 보호한다.
- **소유 개념** 이 있다 : Lock 을 건 스레드만 Unlock 할 수 있다.
- 값은 0 또는 1 의 상태만 가진다 (이진 형태).

```
[Lock] → 임계 영역 → [Unlock]
```

### 특징
- 한 번에 하나의 스레드만 자원에 접근할 수 있다.
- 다른 스레드는 Lock 이 풀릴 때까지 대기한다.

<br><br><br>

# Semaphore
- **정수 변수** 를 사용해 동시 접근 가능한 스레드 수를 제한한다.
- `P (wait)` : 값을 1 감소, 0 이하면 대기
- `V (signal)` : 값을 1 증가, 대기 중인 스레드를 깨움
- 소유 개념이 **없다.** 다른 스레드가 signal 할 수 있다.

### 종류
- **Binary Semaphore** : 값이 0 또는 1 만 가능 (Mutex 와 유사하지만 소유 개념이 없음)
- **Counting Semaphore** : 값이 여러 개 가능 (N 개의 자원을 동시에 접근 허용)

```swift
// DispatchSemaphore 로 최대 3 개 스레드만 동시 접근 허용
let semaphore = DispatchSemaphore(value: 3)

for i in 0..<10 {
    DispatchQueue.global().async {
        semaphore.wait()      // 값을 1 감소
        // 최대 3 개의 스레드만 여기 진입
        print("Task \(i) running")
        sleep(1)
        semaphore.signal()    // 값을 1 증가
    }
}
```

# Monitor
- 객체지향 언어에서 동기화를 지원하기 위한 **고수준** 동기화 도구.
- 하나의 객체 안에 **공유 자원** 과 **접근 함수** 를 함께 캡슐화한다.
- Java 의 `synchronized`, Swift 의 `actor` 가 이에 해당한다.
- Mutex 보다 사용이 쉽고 실수가 적다.

```swift
actor Counter {
    private var value = 0
    
    func increment() { value += 1 }
    func get() -> Int { value }
}

// 사용
let counter = Counter()
await counter.increment()   // actor 는 자동으로 동기화됨
```

# Mutex vs Semaphore

| 구분 | Mutex | Semaphore |
|---|---|---|
| 값 | 0 또는 1 | 0 이상의 정수 |
| 소유권 | 있음 (Lock 건 스레드만 Unlock 가능) | 없음 |
| 용도 | **상호 배제** | **자원 수 제한 및 이벤트 알림** |
| 스레드 간 신호 | 불가 | 가능 |

- **일반적으로 Semaphore 가 Mutex 보다 더 범용적** 이다.
- Mutex 는 Semaphore 의 특수한 형태로 볼 수 있지만, **소유권** 이 있어 구현과 의미가 다르다.

# Swift 에서의 동기화

### 1. DispatchQueue (Serial Queue)
- Serial Queue 에 작업을 넣으면 순차적으로 실행되므로 암묵적으로 동기화된다.

```swift
let queue = DispatchQueue(label: "com.example.serial")
var counter = 0
queue.sync { counter += 1 }
```

### 2. NSLock
- 가장 단순한 Mutex 구현.

```swift
let lock = NSLock()
lock.lock()
// 임계 영역
lock.unlock()
```

### 3. DispatchSemaphore
- 자원 개수 제어에 사용한다.

### 4. actor (Swift 5.5+)
- Swift Concurrency 의 동기화 프리미티브.
- Actor 내부 상태는 자동으로 동기화되어 **Data Race 를 컴파일 타임에 방지** 한다.

### 5. @MainActor
- 특정 코드가 메인 스레드에서 실행되도록 강제한다. UI 업데이트에 주로 사용한다.

# 면접 예상 질문
- **Q. Mutex 와 Semaphore 의 차이점은?**
  - Mutex 는 **소유권** 이 있는 Lock 으로 Lock 을 건 스레드만 Unlock 할 수 있고 값이 0 또는 1 뿐입니다. Semaphore 는 소유권이 없고 정수 값을 가져 여러 스레드가 동시에 자원에 접근하도록 허용할 수 있으며, 스레드 간 이벤트 알림에도 사용합니다.

- **Q. Race Condition 이란 무엇인가요?**
  - 여러 스레드가 동시에 공유 자원에 접근할 때 **실행 순서에 따라 결과가 달라지는** 현상입니다. 예를 들어 `counter += 1` 은 읽기-증가-쓰기의 세 단계로 구성되므로 동기화 없이 여러 스레드가 실행하면 일부 증가가 유실될 수 있습니다.

- **Q. Critical Section 문제를 해결하기 위한 조건은?**
  - **Mutual Exclusion** (상호 배제), **Progress** (진행), **Bounded Waiting** (한정 대기) 세 조건을 만족해야 합니다. 즉 한 번에 하나의 스레드만 진입하고, 진입을 원하는 스레드가 있다면 반드시 누군가는 진입해야 하며, 무한히 대기해서는 안 됩니다.

- **Q. Swift 에서 Thread-safe 하게 값을 관리하려면?**
  - 여러 방법이 있습니다. Serial DispatchQueue, NSLock, DispatchSemaphore 를 사용할 수 있고, Swift 5.5 부터는 **actor** 를 사용하면 컴파일 타임에 Data Race 를 방지할 수 있어 가장 안전합니다.

- **Q. 동기화와 Deadlock 의 관계는?**
  - 동기화 도구(Lock, Semaphore) 를 사용할 때 여러 자원에 대한 Lock 을 잘못 사용하면 Deadlock 이 발생할 수 있습니다. Deadlock 의 4 가지 조건 중 **점유와 대기**, **순환 대기** 가 동기화 과정에서 주로 발생하며, Lock 획득 순서를 일관되게 유지하거나 timeout 을 사용해 방지합니다.
