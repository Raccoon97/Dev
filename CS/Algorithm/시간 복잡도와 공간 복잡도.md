# 복잡도란?
- 알고리즘의 **효율성** 을 측정하는 척도이다.
- 입력 크기 `N` 에 따라 알고리즘이 소비하는 **시간** 과 **공간** 이 어떻게 변하는지를 나타낸다.
- 실제 실행 시간은 하드웨어, 언어 등에 따라 달라지므로, **입력 크기의 증가에 따른 증가 경향** 으로 측정한다.

<br><br><br>

# 시간 복잡도 (Time Complexity)
- 알고리즘이 수행되는 데 필요한 **연산의 횟수** 를 입력 크기에 대한 함수로 나타낸 것이다.

### 3 가지 경우
- **Best Case (최선)** : 가장 빠르게 실행되는 경우 (예 : 정렬된 배열에서 첫 번째가 탐색 대상)
- **Average Case (평균)** : 평균적인 경우
- **Worst Case (최악)** : 가장 느리게 실행되는 경우

> 일반적으로 **Worst Case** 를 기준으로 판단한다.

<br><br><br>

# 점근 표기법

### Big-O 표기법 `O(f(n))`
- **상한(Upper Bound)** 을 나타낸다. "이보다 느리진 않다."
- 가장 일반적으로 사용되는 표기법.

### Big-Ω (오메가) 표기법 `Ω(f(n))`
- **하한(Lower Bound)** 을 나타낸다. "이보다 빠르진 않다."

### Big-Θ (세타) 표기법 `Θ(f(n))`
- **평균(Tight Bound)** 을 나타낸다. Big-O 와 Big-Ω 가 같을 때 사용한다.

<br><br><br>

# Big-O 의 종류

| 표기 | 이름 | 예시 |
|---|---|---|
| `O(1)` | Constant | 배열 인덱스 접근, Hash Table 조회 |
| `O(log N)` | Logarithmic | 이진 탐색, BST 탐색 |
| `O(N)` | Linear | 선형 탐색, 단순 반복문 |
| `O(N log N)` | Log-Linear | Merge Sort, Quick Sort (평균), Heap Sort |
| `O(N²)` | Quadratic | Bubble Sort, Insertion Sort, 이중 반복문 |
| `O(N³)` | Cubic | 삼중 반복문 |
| `O(2ⁿ)` | Exponential | 피보나치 재귀 |
| `O(N!)` | Factorial | 완전 순열 탐색, 외판원 문제 |

### 성능 비교 (N 이 커질수록)
`O(1)` < `O(log N)` < `O(N)` < `O(N log N)` < `O(N²)` < `O(2ⁿ)` < `O(N!)`

# 공간 복잡도 (Space Complexity)
- 알고리즘이 수행되는 데 필요한 **메모리 공간** 을 입력 크기에 대한 함수로 나타낸 것이다.
- **고정 공간** (입력과 무관) + **가변 공간** (입력에 따라 달라짐)

### 예시

```swift
// O(1) - 입력 크기와 무관
func sum(_ nums: [Int]) -> Int {
    var total = 0
    for num in nums { total += num }
    return total
}

// O(N) - 입력 크기에 비례
func copy(_ nums: [Int]) -> [Int] {
    var result: [Int] = []
    for num in nums { result.append(num) }
    return result
}
```

### 시간과 공간의 Trade-off
- **Memoization** 처럼 공간을 더 사용해 시간을 단축하는 기법이 있다.
- 반대로 메모리가 부족하면 시간을 희생하기도 한다.

# 자료구조별 시간 복잡도

| 자료구조 | 접근 | 검색 | 삽입 | 삭제 |
|---|---|---|---|---|
| **Array** | O(1) | O(N) | O(N) | O(N) |
| **Linked List** | O(N) | O(N) | O(1) | O(1) |
| **Stack** | O(N) | O(N) | O(1) | O(1) |
| **Queue** | O(N) | O(N) | O(1) | O(1) |
| **Hash Table** | N/A | O(1) | O(1) | O(1) |
| **BST (균형)** | O(log N) | O(log N) | O(log N) | O(log N) |
| **BST (최악)** | O(N) | O(N) | O(N) | O(N) |
| **AVL / Red-Black** | O(log N) | O(log N) | O(log N) | O(log N) |

# 면접 예상 질문
- **Q. 시간 복잡도란 무엇인가요?**
  - 입력 크기 N 에 따라 알고리즘의 연산 횟수가 어떻게 증가하는지를 나타내는 척도입니다. 실제 수행 시간이 아닌 **증가 경향** 을 나타내며, 보통 최악의 경우(Worst Case) 를 Big-O 표기법으로 나타냅니다.

- **Q. O(N) 과 O(log N) 의 차이는?**
  - O(N) 은 입력 크기에 비례해 연산 수가 증가하고, O(log N) 은 로그 함수적으로 증가합니다. 예를 들어 N 이 100 만이면 O(N) 은 100 만 번 연산하지만, O(log N) 은 약 20 번만 연산합니다. 이진 탐색이 대표적인 O(log N) 알고리즘입니다.

- **Q. 시간 복잡도가 같으면 실행 속도도 같은가요?**
  - 아닙니다. Big-O 는 **상수항과 낮은 차수의 항을 무시** 하므로, 같은 Big-O 라도 실제 상수 계수에 따라 실행 속도가 다를 수 있습니다. 예를 들어 Quick Sort 와 Merge Sort 는 모두 O(N log N) 이지만 실제 성능은 다릅니다.

- **Q. 공간 복잡도도 중요한가요?**
  - 네, 임베디드나 모바일처럼 메모리가 제한적인 환경에서는 매우 중요합니다. iOS 에서도 메모리 부족 시 앱이 강제 종료될 수 있으므로 대용량 데이터를 다룰 때는 공간 복잡도를 신경 써야 합니다.

- **Q. 재귀 함수의 시간/공간 복잡도는 어떻게 계산하나요?**
  - 시간 복잡도는 재귀 호출 횟수와 각 호출의 비용을 곱해 계산합니다. 공간 복잡도는 **재귀 호출 깊이만큼 호출 스택** 을 사용하므로 `O(재귀 깊이)` 가 됩니다. 예를 들어 피보나치 재귀는 시간 `O(2ⁿ)`, 공간 `O(N)` 입니다.
