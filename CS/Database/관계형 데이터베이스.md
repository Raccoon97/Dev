# 관계형 데이터베이스란?
- **RDBMS (Relational DataBase Management System)** 는 **관계형 모델** 을 기반으로 하는 데이터베이스이다.
- 데이터를 **Table (Relation)** 형태로 저장하고, 테이블 간의 **관계 (Relationship)** 로 데이터를 연결한다.
- 대표 DBMS : Oracle, MySQL, PostgreSQL, MariaDB, SQL Server

<br><br><br>

# 주요 용어

| 용어 | 설명 |
|---|---|
| **Table (Relation)** | 데이터가 저장되는 2 차원 구조 |
| **Row (Tuple, Record)** | 테이블의 각 행, 하나의 데이터 단위 |
| **Column (Attribute, Field)** | 테이블의 각 열, 데이터의 속성 |
| **Domain** | 하나의 속성이 가질 수 있는 값의 집합 |
| **Degree** | 테이블의 속성(Column) 개수 |
| **Cardinality** | 테이블의 튜플(Row) 개수 |
| **Schema** | 데이터베이스의 구조와 제약 조건을 정의 |

<br><br><br>

# Key 의 종류

### 1. Super Key (슈퍼키)
- 튜플을 유일하게 식별할 수 있는 속성들의 집합.
- **유일성** 은 만족하지만 **최소성** 은 만족하지 않아도 된다.

### 2. Candidate Key (후보키)
- 유일성과 최소성을 모두 만족하는 속성의 집합.
- 기본키가 될 수 있는 후보들이다.

### 3. Primary Key (기본키)
- 후보키 중에서 선택된 하나의 키.
- **NULL 불가**, **중복 불가**
- 테이블당 하나만 존재한다.

### 4. Alternate Key (대체키)
- 후보키 중 기본키로 선택되지 않은 나머지 키.

### 5. Foreign Key (외래키)
- 다른 테이블의 기본키를 참조하는 키.
- 참조 무결성을 유지한다.

<br><br><br>

# 무결성 제약조건
1. **개체 무결성 (Entity Integrity)** : 기본키는 NULL 이나 중복값을 가질 수 없다.
2. **참조 무결성 (Referential Integrity)** : 외래키는 참조되는 테이블의 기본키 값이거나 NULL 이어야 한다.
3. **도메인 무결성 (Domain Integrity)** : 각 속성의 값은 정의된 도메인에 속해야 한다.
4. **사용자 정의 무결성** : 사용자가 정의한 비즈니스 규칙을 따라야 한다.

<br><br><br>

# 정규화 (Normalization)
- 데이터의 중복을 줄이고 이상 현상 (Anomaly) 을 방지하기 위해 테이블을 분해하는 과정이다.
- 이상 현상 : **삽입 이상, 갱신 이상, 삭제 이상**

### 1NF (제 1 정규형)
- 모든 속성이 **원자값 (Atomic Value)** 을 가져야 한다.
- 즉, 하나의 컬럼에 여러 값이 들어가면 안 된다.

### 2NF (제 2 정규형)
- 1NF 를 만족하고, 기본키에 대한 **완전 함수 종속** 을 만족해야 한다.
- 부분 함수 종속 (기본키의 일부에만 종속) 을 제거한다.

### 3NF (제 3 정규형)
- 2NF 를 만족하고, **이행적 함수 종속** 을 제거해야 한다.
- A → B, B → C 의 형태가 있으면 안 된다.

### BCNF (Boyce-Codd Normal Form)
- 3NF 보다 엄격한 정규형으로, 모든 결정자가 후보키여야 한다.

### 반정규화 (Denormalization)
- 성능 향상을 위해 의도적으로 정규화를 거꾸로 진행하는 것.
- JOIN 을 줄이기 위해 일부 중복을 허용한다.

<br><br><br>

# Join

| Join 종류 | 설명 |
|---|---|
| **INNER JOIN** | 양쪽 테이블 모두 일치하는 행만 |
| **LEFT OUTER JOIN** | 왼쪽 테이블 전체 + 오른쪽의 일치하는 행 |
| **RIGHT OUTER JOIN** | 오른쪽 테이블 전체 + 왼쪽의 일치하는 행 |
| **FULL OUTER JOIN** | 양쪽 테이블 전체 (일치하지 않으면 NULL) |
| **CROSS JOIN** | 두 테이블의 카테시안 곱 |
| **SELF JOIN** | 자기 자신과 JOIN |

```sql
-- INNER JOIN 예시
SELECT u.name, p.title
FROM users u
INNER JOIN posts p ON u.id = p.user_id;

-- LEFT JOIN 예시 (게시글이 없는 사용자도 포함)
SELECT u.name, p.title
FROM users u
LEFT JOIN posts p ON u.id = p.user_id;
```

# 면접 예상 질문
- **Q. 정규화를 하는 이유는?**
  - 데이터의 중복을 줄여 저장 공간을 절약하고, 삽입/갱신/삭제 이상을 방지해 데이터의 무결성을 유지하기 위함입니다. 다만 정규화가 과도하면 JOIN 이 많아져 성능이 저하될 수 있어, 상황에 따라 반정규화를 병행하기도 합니다.

- **Q. 기본키(PK) 와 외래키(FK) 의 차이는?**
  - 기본키는 테이블 내에서 튜플을 유일하게 식별하는 키로 NULL 과 중복을 허용하지 않고, 외래키는 다른 테이블의 기본키를 참조하는 키로 참조 무결성을 유지합니다.

- **Q. INNER JOIN 과 LEFT JOIN 의 차이는?**
  - INNER JOIN 은 양쪽 테이블 모두에 매칭되는 행만 결과에 포함하고, LEFT JOIN 은 왼쪽 테이블의 모든 행을 포함하며 매칭되지 않는 오른쪽 컬럼은 NULL 로 표시됩니다.

- **Q. 정규화와 반정규화는 언제 사용하나요?**
  - 일반적으로 설계 단계에서는 3NF 까지 정규화해 데이터 무결성을 확보하고, 조회 성능이 중요한 경우 (읽기 중심의 OLAP, 대시보드 등) 의도적으로 반정규화를 적용해 JOIN 비용을 줄입니다.

- **Q. NULL 값이란?**
  - 값이 없음을 나타내는 특수한 값으로, 0 이나 빈 문자열과는 다릅니다. NULL 과의 비교는 `=` 가 아닌 `IS NULL` 을 사용해야 하며, 집계 함수에서는 NULL 이 무시됩니다.
