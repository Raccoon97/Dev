# 객체지향 프로그래밍이란?
- **OOP (Object-Oriented Programming)** 는 현실 세계의 사물을 **객체(Object)** 로 모델링해 프로그램을 구성하는 패러다임이다.
- 데이터(속성) 와 행위(메서드) 를 하나의 객체로 묶어 관리한다.
- 대표 언어 : Swift, Java, C++, Python, Kotlin

<br><br><br>

# OOP 의 4 가지 특성

### 1. Encapsulation (캡슐화)
- 데이터와 해당 데이터를 조작하는 메서드를 하나의 단위로 묶는 것.
- 외부에서 내부 구현을 직접 접근하지 못하도록 **정보 은닉** 한다.
- 접근 제어자 (`private`, `fileprivate`, `internal`, `public`, `open`) 를 사용한다.

```swift
class BankAccount {
    private var balance: Double = 0
    
    func deposit(_ amount: Double) {
        guard amount > 0 else { return }
        balance += amount
    }
    
    func getBalance() -> Double {
        return balance
    }
}
```

### 2. Inheritance (상속)
- 기존 클래스의 속성과 메서드를 **자식 클래스가 물려받는** 것.
- 코드의 재사용성을 높인다.
- **Is-A** 관계 : "자식 클래스는 부모 클래스의 한 종류이다."

```swift
class Animal {
    func speak() { print("Sound") }
}

class Dog: Animal {
    override func speak() { print("Woof") }
}
```

### 3. Polymorphism (다형성)
- **같은 이름** 의 메서드가 **다른 동작** 을 할 수 있는 특성.
- **Overriding** (재정의) : 부모의 메서드를 자식이 재정의
- **Overloading** (오버로딩) : 같은 이름의 메서드를 매개변수를 다르게 여러 개 정의

### 4. Abstraction (추상화)
- 복잡한 시스템에서 **핵심적인 개념만 표현** 하고 불필요한 세부사항은 숨기는 것.
- Swift 에서는 `protocol` 이나 `class` 의 `abstract` 개념으로 구현한다.

```swift
protocol Vehicle {
    var speed: Double { get }
    func start()
    func stop()
}
```

# 클래스와 객체
- **Class (클래스)** : 객체를 만들기 위한 **설계도 / 틀**
- **Object (객체)** : 클래스로부터 만들어진 **실체 (Instance)**
- **Instance (인스턴스)** : 메모리에 할당된 객체

<br><br><br>

# 객체지향 vs 절차지향

| 구분 | 객체지향 | 절차지향 |
|---|---|---|
| 중심 | 객체와 메시지 | 함수와 데이터 |
| 구조 | Bottom-Up | Top-Down |
| 데이터 접근 | 캡슐화로 보호 | 전역 데이터 공유 |
| 재사용성 | 높음 | 낮음 |
| 확장성 | 높음 | 낮음 |
| 실행 속도 | 상대적으로 느림 | 상대적으로 빠름 |
| 대표 언어 | Swift, Java, C++ | C, Fortran |

<br><br><br>

# OOP 의 장단점

### 장점
- **재사용성** 이 높다 (상속, 다형성).
- **유지보수** 가 쉽다 (캡슐화).
- 현실 세계를 모델링하기 직관적이다.
- 코드의 **확장성** 이 좋다.

### 단점
- 설계 난이도가 높다.
- 실행 속도가 절차지향에 비해 느릴 수 있다.
- 객체 생성 비용이 크다.
- 잘못 설계하면 오히려 복잡해진다.

# 면접 예상 질문
- **Q. 객체지향 프로그래밍의 4 가지 특성은?**
  - **캡슐화(Encapsulation)**, **상속(Inheritance)**, **다형성(Polymorphism)**, **추상화(Abstraction)** 입니다. 캡슐화는 데이터와 메서드를 하나로 묶고 정보를 은닉하는 것, 상속은 기존 클래스를 재사용하는 것, 다형성은 같은 이름의 메서드가 다르게 동작하는 것, 추상화는 핵심 개념만 표현하는 것입니다.

- **Q. Swift 에서 Class 와 Struct 의 차이는?**
  - Class 는 **참조 타입 (Reference Type)** 이고 힙에 할당되며 상속이 가능합니다. Struct 는 **값 타입 (Value Type)** 이고 스택에 할당되며 상속이 불가능하지만 protocol 채택은 가능합니다. Swift 는 기본적으로 Struct 를 권장하며, 참조 의미가 필요하거나 상속이 필요한 경우에만 Class 를 사용합니다.

- **Q. Overriding 과 Overloading 의 차이는?**
  - Overriding 은 **부모 클래스의 메서드를 자식 클래스에서 재정의** 하는 것으로 상속 관계에서 발생합니다. Overloading 은 **같은 이름의 메서드를 매개변수 타입이나 개수를 다르게** 여러 개 정의하는 것입니다. Swift 는 둘 다 지원합니다.

- **Q. 상속보다 구성(Composition) 을 선호하라는 말은?**
  - 상속은 강한 결합을 만들고 변경에 취약합니다. 구성은 객체가 다른 객체를 포함(Has-A) 하는 방식으로, 더 유연하고 변경에 강한 설계를 할 수 있습니다. Swift 에서는 protocol + extension 을 이용한 **Protocol-Oriented Programming** 이 이를 잘 구현합니다.

- **Q. 캡슐화가 왜 중요한가요?**
  - 객체의 내부 상태를 외부로부터 보호해 무결성을 유지하고, 구현 세부사항을 숨겨 외부 코드와의 결합도를 낮춥니다. 결과적으로 내부 구현이 바뀌어도 외부 코드에 영향이 없어 **유지보수성** 이 향상됩니다.
